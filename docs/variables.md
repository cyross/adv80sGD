# adv80sGD：変数の扱い方・書き方

## 変数の種類と有効範囲

ゲームの中で読める「名前の付いた値」は、書き場所と名前の頭で五つに分かれます。

| 種類 | 書き場所・名前 | 読める範囲 | 書き換え | セーブ |
| --- | --- | --- | --- | --- |
| 変数（フラグを含む） | シナリオかプロジェクト設定の `variables`（宣言は任意） | すべての JSON シナリオ。同じ名前の Ink の `VAR` とも値を受け渡す | できる | 入る |
| 定数 | シナリオかプロジェクト設定の `constants` | すべてのシナリオ | できない（実行時は無視して警告、確認で `CONST_WRITE`） | 入らない（いつも設定の値） |
| 引数 | `arg.名前`（サブシーンの `params`） | そのサブシーンの中だけ | できない | 呼び出しの途中も入る |
| システムの値 | `sys.名前`（フレームワークが入れる） | タイトル・おまけ・システムシーンなど（後の節） | できない | 入らない |
| 持ち物 | シナリオの `items` | `has(ID)`、`count(ID)` | `item.add`、`item.remove` | 入る |

- 変数に「シーンの中だけ」「会話の中だけ」のような狭い範囲はありません。どこで宣言しても、ゲーム全体で一つの名前の場に入ります。
- フラグは、真偽値（true / false）を入れた変数のことです。別の仕組みではありません。
- 訪れたシーン、見た会話、読んだ行、選んだ選択肢は、変数とは別に自動で記録されます（`visited(…)`、`talked(…)`、`read(…)`、`chosen(…)` で読む）。「この会話を見た」を表すためにフラグを作る必要はありません。

## 名前の付け方と書き方

変数は宣言しなくても使えますが、宣言しておくと初めの値が決まり、確認とエディタの候補にも出ます。物語全体で使うものは `_scenario.scenario.json` に、シナリオをまたぐものはプロジェクト設定に書きます。

```json
"variables": {
  "money":     { "type": "int",    "default": 0 },
  "met_ayumi": { "type": "bool",   "default": false },
  "player":    { "type": "string", "default": "ゆうじ" }
},
"constants": { "MAX_HP": 99 }
```

**名前の決まり**

- 空白と、式で使う記号（`( ) ! = < > & | + - * / % , ;` と引用符）は使えません。`and`・`or`・`not`・`true`・`false` も名前になりません。
- `sys.` と `arg.` で始まる名前は、システムの値と引数に使われているので、自分の変数には使いません。

**勧める付け方**

| ことがら | 例 | わけ |
| --- | --- | --- |
| 英小文字と `_` | `met_ayumi`、`door_unlocked` | Ink の `VAR` と同じ名前で受け渡せる |
| フラグは「起きたこと」を過去形で | `door_unlocked`、`talked_to_boss` | 条件式が文として読める |
| 定数は大文字 | `MAX_HP` | 書き換えられないものだと分かる |
| 章だけで使うものは頭を付ける | `ch2_clues` | 全体で一つの名前の場なので、ぶつからない |

プロジェクト設定と同じ名前の変数・定数をシナリオでも宣言すると、シナリオの宣言が使われ、確認で警告が出ます。同じ名前は一か所だけに書きます。

## 値の型と初めの値

| type | 値 | JSON での書き方 | 式での書き方 |
| --- | --- | --- | --- |
| `bool` | 真偽値 | `true`、`false` | `true`、`false` |
| `int` | 整数 | `100` | `100` |
| `float` | 小数 | `0.5` | `0.5` |
| `string` | 文字列 | `"ゆうじ"` | `"ゆうじ"` か `'ゆうじ'` |

**初めの値**：宣言の `default` が、始める前の値です。一度も書き換えていない変数を読むと、この値が返ります。「はじめから」で始める前の状態に戻るときも、この値に戻ります。

**値のない変数**：`default` のない宣言や、宣言も書き換えもしていない変数は、使う場所に合わせて `false`・`0`・空の文字列として扱われます。宣言も書き換えもしていない変数を読むと、開発中（デバッグビルド）は `UNKNOWN_VARIABLE` の警告が出ます。打ち間違いもこの警告で見つかるので、宣言しておく方が安全です。

**型の混ぜ方**：

- 比べるとき、数どうしは整数と小数を区別しません（`1 == 1.0`）。大小の比較は、文字列でも数として読めれば数として比べます。
- 足し算は、どちらかが文字列ならつなぎます（`"なまえ：" + player`）。
- 整数どうしの割り算は整数になります（`7 / 2` は `3`）。0 で割ると 0 です。
- 変数に入るのは、入れた値そのものです。`int` と宣言した変数に文字列を入れないよう、書く側でそろえます。

**Ink の LIST**：Ink の LIST の変数は、JSON 側からは「項目名, 項目名」の文字列として見えます。

## 変える・読む・文に埋め込む

**変える**（手順に書く）

| 書き方 | 例 | 使いどころ |
| --- | --- | --- |
| `set` に値 | `{"set": {"door_unlocked": true, "player": "ゆうじ"}}` | フラグを立てる・値をそのまま入れる |
| `set` に `=` で始まる式 | `{"set": {"money": "= money - price * 2"}}` | 今の値から計算する |
| `let` | `{"let": "money = money - 10; visits = visits + 1"}` | 計算をまとめて書く（`;` で区切る） |
| `state.set` の `op` | `{"state.set": {"name": "money", "op": "add", "value": 10}}` | `add`・`sub`・`mul`・`div`・`mod`・`min`・`max`・`toggle` |

- `set` の値で文字列を入れたいとき、`=` で始めなければそのまま文字列になります。`=` で始めたい文字列は、式の中で `"= \"=を含む文\""` のように引用符で囲みます。
- 一つの `set` に複数書くとき、同じ手順の中の他の変数を使う計算は `let` に分けると、順番がはっきりします（`let` は書いた順に入る）。
- 持ち物は変数ではなく `{"item.add": {"id": "key"}}`・`{"item.remove": {"id": "key"}}` で変えます。

**読む**

- 条件式：`"door_unlocked"`、`"money >= 100"`、`"player == \"ゆうじ\""`（書き方は[式と条件式の扱い方・書き方](expressions.md)）。
- 式の中では、引用符のない名前は変数として読まれます。文字列と比べるときは必ず引用符で囲みます（`scene == hallway` だけは例外で、シーンID として読む）。

**文に埋め込む**

| 書き方 | 例 |
| --- | --- |
| `{名前}` | `"{player}くん、{money}えん もってる？"` |
| `[var=名前]` | `"[var=player]くん"`（`{…}` と同じ） |
| `[if=条件]…[elif=条件]…[else]…[/if]` | `"いまは [if=money >= 10]ゆうふく[else]びんぼう[/if]。"` |
| `{arg.名前}`、`{sys.名前}`、`{定数}` | `"{arg.item}は {arg.price}えん。"` |

本文のほか、選択肢の `label`、話者の `name`、「おわり」の `text` でも使えます。文字としての `{` を出すときは `{{` と書きます。

## システムの値 sys.* の一覧

`sys.` で始まる値は、フレームワークが場面に合わせて入れる読み取り専用の値です。セーブには入りません。

**全プレイ共通の記録から**（タイトルを始めるときに入る。タイトル・おまけの条件に使う）

| 値 | 内容 |
| --- | --- |
| `sys.endings_seen`、`sys.endings_total` | 見たエンディングの数、`endings` の数 |
| `sys.all_endings` | すべて見たか |
| `sys.ending_<ID>` | そのエンディングを見たか |
| `sys.opening_replay` | オープニングを見返せるか |
| `sys.extras` | おまけを開けるか |
| `sys.gallery_opened`、`sys.gallery_total`、`sys.gallery_all` | ギャラリーの開いた数・全部の数・全部開いたか（特典を除く） |
| `sys.music_opened`、`sys.music_total`、`sys.music_all` | 音楽の同じもの |
| `sys.extras_opened`、`sys.extras_total` | ギャラリーと音楽の合計 |

**システムシーンの中だけ**

| 値 | 内容 |
| --- | --- |
| `sys.mode` | `save`・`load`・`settings`・`log` |
| `sys.slot_count` | セーブ枠の数 |
| `sys.slot_<枠>`、`sys.slot_<枠>_exists`、`sys.slot_<枠>_label` | 枠の説明（日時とシーン名）、セーブがあるか、枠の名前（枠は `01`、`quick`、`auto1` など） |
| `sys.<設定のキー>` | `text_speed`、`bgm_volume` などの設定の値 |
| `sys.feature_<キー>` | モダン機能が入っているか |

場面に合わない `sys.` の値（ゲームの途中で `sys.mode` など）は入っていないので、値のない変数と同じく `false`・`0`・空になります。

## セーブ・周回との関係

値は、「セーブごとの状態」と「全プレイ共通の記録」のどちらかに入ります。周回をまたいで残したいものを、普通の変数で作らないように注意します。

| | セーブごとの状態 | 全プレイ共通の記録 |
| --- | --- | --- |
| 入るもの | 変数、持ち物、いまのシーン、訪れた・見た・読んだ・選んだ記録、手帳・目的・ヒント、サブシーンの呼び出し、Ink の位置 | 見たエンディング、見たオープニング、既読、見た画像・聞いた曲、フローチャートの到達点 |
| 入らないもの | 定数、`sys.*` | 変数 |
| 「はじめから」で | 初めの値に戻る | 残る |
| 読み方 | 変数の名前、`has(…)` など | `sys.endings_seen` など |

**周回で変えたいとき**：「二周目は少し違う」は、変数ではなく `sys.endings_seen >= 1` や `sys.ending_good` で分けます。タイトルの `variants`、おまけの `when`、メニューの `when` などがそのための場所です。

**変数ごと次の周へ持ち越すとき**：「おわり」の `save_prompt: true` でクリアデータをセーブさせ、`save_carry` で引き継ぐものを選びます（`"all"`・`"none"`・`{"vars": ["money", "hero_name"], "items": "all", …}`）。クリアデータをロードすると、`save_resume` のシーンから始まります。

**システムシーンの中**：JSON のシステムシーンの中で変えた変数は、閉じると開く前の値に戻ります。残したい設定は `settings.set` で書きます。

**Ink との受け渡し**：Ink に入るとき、同じ名前の `VAR` に変数の値を写し、Ink の中で変わった値は戻します（プロジェクト設定 `ink.sync_variables: false` で戻さない）。セーブには戻したあとの値が入ります。

## つまずきやすいところ

| 起きること | わけ | どうするか |
| --- | --- | --- |
| 条件がいつも成り立たない | 変数名の打ち間違い（値のない変数は false） | 宣言する。「adv80s」画面の「変数の一覧」、デバッグの `UNKNOWN_VARIABLE` を見る |
| `player == ゆうじ` が合わない | 引用符のない `ゆうじ` が変数として読まれる | `player == "ゆうじ"` |
| 定数が変わらない | 定数は書き換えられない（セーブにも入らない） | 変える値は `variables` にする |
| 周回したら値が消えた | 「はじめから」で初めの値に戻る | `sys.*` で分けるか、クリアデータで引き継ぐ |
| 宣言したのに別の初めの値になる | プロジェクト設定とシナリオの両方で宣言している（シナリオが優先） | 一か所だけに書く |
| Ink と値がずれる | 名前が違うか、`ink.sync_variables` が false | 同じ名前の `VAR` を書く |
| 文に `{` が出ない | `{…}` は変数の差し込み | `{{` と書く |
| 持ち物を `set` で増やせない | 持ち物は変数と別 | `item.add`・`item.remove` |

遊んでいる途中の値は、デバッグ実行のコンソールで見られます。`vars` で一覧、`get 名前`（式も可）で一つ、`set 名前 値` か `名前 = 値` で書き換え、`toggle 名前` でフラグを反転します。変数をそろえてから試したいときは、シナリオエディタの「ひな形…」で値を書いて「▶ このシーンから実行」します。
