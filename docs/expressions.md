# adv80sGD：式と条件式の扱い方・書き方

## 式を使う場所

式には、真か偽かを決める**条件式**と、値を作る**計算式**の二つがあります。書き方は共通で、どちらもフレームワーク独自の小さなパーサーで読みます（Godot の Expression は使いません）。

| 種類 | 書く場所 | 例 |
| --- | --- | --- |
| 条件式 | 手順の `if` | `{"if": "has(key)", "then": …}` |
| 条件式 | `when`（選択肢の項目、もの・出口・スプライト、重ねる背景、話題、タイトルのメニューと `variants`、おまけ、意図スキーマの層 など） | `"when": "not got_key"` |
| 条件式 | 文中の `[if=条件]…[elif=条件]…[else]…[/if]` | `"[if=money >= 10]ゆうふく[/if]"` |
| 条件式 | Ink の外部関数 `cond("…")` | `{cond("has(key) and visited(cellar)")}` |
| 計算式 | `let` | `{"let": "money = money - 10"}` |
| 計算式 | `set` の `=` で始まる値 | `{"set": {"money": "= money * 2"}}` |
| 計算式 | サブシーンの `args`・`return` の `=` で始まる値 | `{"return": "=arg.price * 2"}` |
| どちらも | デバッグコンソールの `get 式` | `get money >= 100` |

条件式には、短い文字列の形と JSON の形があります。JSON の形が正式で、短い文字列は読み込むときに JSON の形へ変えられます。人が書くなら短い形、ツールで作るなら JSON の形が向いています。

```text
"has_key and money >= 100 and (visited(cellar) or has(lamp)) and not scene == hallway"

{ "all": [
    "has_key",
    { "var": "money", "ge": 100 },
    { "any": [ { "visited": "cellar" }, { "has": "lamp" } ] },
    { "not": { "scene": "hallway" } }
] }
```

## 書き方の基本

| 書くもの | 書き方 | 例 |
| --- | --- | --- |
| 数 | そのまま（小数点があれば小数） | `100`、`0.5` |
| 文字列 | `"…"` か `'…'` で囲む | `"ゆうじ"`、`'ゆうじ'` |
| 真偽値 | `true`、`false` | `met_ayumi == true` |
| 変数・定数 | 名前をそのまま | `money`、`MAX_HP`、`arg.price`、`sys.endings_seen` |
| 組み込みの関数 | `名前(引数, …)` | `has(key)`、`chosen(who, detective)` |
| まとまり | `( … )` | `(visited(cellar) or has(lamp))` |

- 空白はいくつ入れても同じです。全角の空白も空白として読みます。
- 引用符のない名前は**変数**です。文字列として比べたいときは囲みます。ただし組み込みの関数の引数（`has(key)` の `key`）と、`scene`・`preset`・`group` との `==`・`!=`（`scene == hallway`）だけは、囲まなくても ID として読みます。
- JSON の文字列の中に式を書くので、`"` を使うときは `\"` と書きます。`'` を使えば書かずに済みます。

```json
{ "if": "player == 'ゆうじ'", "then": … }
{ "if": "player == \"ゆうじ\"", "then": … }
```

**フラグ名だけの条件**：`"has_key"` のように名前だけを書くと、その変数が「真とみなせる」ときに成り立ちます。真とみなされるのは、`true`、0 でない数、空でない文字列です。

**条件としての配列と真偽値**：JSON の形では、`true`・`false` をそのまま書け、配列は「すべて満たす」（`all` と同じ）です。条件を書かないときは、いつも成り立ちます。

## 演算子と優先順位

上ほど先にまとまります（優先順位が高い）。迷ったら括弧で囲みます。

| 順位 | 演算子 | 意味 | JSON の形 |
| --- | --- | --- | --- |
| 1 | `( )`、関数 | まとまり、組み込みの関数 | `{"has": …}` など |
| 2 | `-`（前に付く） | 符号を反転 | — |
| 3 | `*`、`/`、`%` | 掛け算、割り算、余り | — |
| 4 | `+`、`-` | 足し算（文字列ならつなぐ）、引き算 | — |
| 5 | `==`、`!=`、`<`、`<=`、`>`、`>=` | 比べる | `eq`、`ne`、`lt`、`le`、`gt`、`ge` |
| 6 | `not`、`!` | 満たさない | `{"not": …}` |
| 7 | `and`、`&&` | すべて満たす | `{"all": […]}` |
| 8 | `or`、`\|\|` | どれかを満たす | `{"any": […]}` |

- `not` は比較より後にまとまるので、`not scene == hallway` は「`scene == hallway` ではない」という意味になります。
- 比較は一つの式に一つです。`0 < x < 10` は書けないので、`x > 0 and x < 10` と書きます。
- `and` と `or` を混ぜるときは、`and` が先にまとまります。`a or b and c` は `a or (b and c)` です。
- 「いずれかと等しい」は JSON の形でだけ書けます：`{"var": "weather", "in": ["rain", "snow"]}`。短い形なら `weather == 'rain' or weather == 'snow'`。

**JSON の形の比較**：`{"var": "変数名", "比較": 右辺}` と書きます。右辺には値のほか、`{"var": "別の変数"}` や `{"calc": "計算式"}` も書け、左辺を式にしたいときは `{"calc": "money - price", "ge": 0}` のようにします。比較のキーを一つに二つ書くと、両方を満たすときだけ成り立ちます（`{"var": "x", "gt": 0, "lt": 10}`）。

## 使える関数

使えるのは、状態を調べる組み込みの関数だけです。自分で関数を足すことはできません（計算が要るものは変数に入れてから使います）。

| 関数 | 返すもの | 例 |
| --- | --- | --- |
| `has(持ち物ID)` | 持っているか | `has(key)` |
| `count(持ち物ID)` | いくつ持っているか | `count(coin) >= 3` |
| `visited(シーンID)` | そのシーンを訪れたか | `visited(cellar)` |
| `talked(会話ID)` | その会話を見たか（Ink は `ink:ノット名`） | `talked(ayumi_first)` |
| `read(行ID)` | その行を読んだか | `read(ayumi_key_01)` |
| `chosen(選択肢ID, 項目ID)` | その選択肢でその項目を選んだか | `chosen(who, detective)` |
| `feature(機能名)` | そのモダン機能が入っているか | `feature(notebook)` |
| `scene`、`preset`、`group` | いまのシーン、画面のプリセット、グループ（`==`・`!=` で比べる） | `scene == hallway`、`preset == 98`、`group == console` |

- `preset == 98` は「98」で始まるプリセット（`98.640x400` など）にも合います。機種ごとに文や絵を変えるときに使います。
- 関数は計算式の中でも使えます。`count(…)` は数、ほかは真偽値を返します（`{"let": "coins = count(coin)"}`）。
- 乱数を使う関数はありません。乱数が要るときは Ink の `RANDOM` を使うか、自作の出力イベント（`x.名前`）で変数に入れます。
- `chosen(…)` で調べる選択肢には、選択肢と項目の `id` を手で書いておきます。

## 条件式の書き方と例

| やりたいこと | 条件式 |
| --- | --- |
| フラグが立っている | `door_unlocked` |
| フラグが立っていない | `not door_unlocked` |
| お金が足りる | `money >= price` |
| 計算した結果で比べる | `money - price * 2 >= 0` |
| 範囲に入っている | `hp > 0 and hp < MAX_HP` |
| 名前が「ゆうじ」 | `player == 'ゆうじ'` |
| 鍵を持ち、地下室に行ったかランプがある | `has(key) and (visited(cellar) or has(lamp))` |
| コインが 3 枚以上 | `count(coin) >= 3` |
| あの会話を見たあとだけ | `talked(ayumi_first)` |
| 前に「探偵だ」と答えた | `chosen(who, detective)` |
| このシーン以外 | `not scene == hallway`（`scene != hallway` も同じ） |
| 二周目から | `sys.endings_seen >= 1` |
| GB のときだけ | `preset == GB`（機種 ID は大文字。そのグループなら `group == handheld`） |
| サブシーンの引数で分ける | `arg.price > 5` |

**書く場所ごとの例**

```text
{ "if": "money >= price", "then": [ { "let": "money = money - price" }, "かった。" ], "else": "おかねが たりない。" }

{ "label": "かぎを みせる", "when": "has(key)", "do": [ … ] }

"いまは [if=money >= 10]ゆうふく[elif=money > 0]ふつう[else]びんぼう[/if]。"

"objects": { "key": { "when": "not has(key)", … } }
```

**読みやすく書くコツ**

- 長くなった条件は、意味のある名前のフラグにまとめます。例えば「犯人が分かった」ときに `{"set": {"culprit_known": true}}` としておき、他の場所では `culprit_known` だけを調べます。
- `and` と `or` を混ぜるときは、優先順位に頼らず括弧を付けます。
- 「見た」「訪れた」「選んだ」は自動の記録（`talked`、`visited`、`chosen`）を使い、同じ意味のフラグを作らないようにします。

## 間違いと確かめ方

**書くときに確かめる**：シナリオエディタの条件や `let` の項目には「式…」ボタンがあり、式エディタで書けます。打つと変数・定数・持ち物・関数の候補が出（Ctrl+Space でも）、`visited(` の中ならシーン、`has(` の中なら持ち物だけが並びます。書いた式はその場で確かめられ、誤りがあると理由が出て決定できません。候補にない名前は注意として出ます（新しい変数なら問題ありません）。

**まとめて確かめる**：ドック「adv80s」の「マニフェストを生成」で、すべてのシナリオの式が確かめられます。

| コード | 意味 | よくある原因 |
| --- | --- | --- |
| `COND_SYNTAX`（エラー） | 式を読めない | 括弧の閉じ忘れ、`=` と `==` の取り違え、`0 < x < 10`、条件に計算だけを書いた（`money + 1`）、知らない関数 |
| `UNKNOWN_VARIABLE`（警告） | 宣言も変更もしていない変数を読んでいる | 打ち間違い、文字列を引用符で囲み忘れた |
| `CONST_WRITE`（エラー） | 定数を書き換えようとしている | 変数と定数の名前が同じ |
| `IF_UNCLOSED`（警告） | 文中の `[if]` と `[/if]` の数が合わない | `[/if]` の書き忘れ |

**遊びながら確かめる**：実行中に読めない式に出会うと、その条件は「成り立たない」として扱われ、開発中は警告が出ます。デバッグ実行のコンソールで `get 式`（例：`get money >= price`）と打つと、いまの状態での結果が見られます。`set` で値を変えてからもう一度 `get` すると、分岐の境目を試せます。
